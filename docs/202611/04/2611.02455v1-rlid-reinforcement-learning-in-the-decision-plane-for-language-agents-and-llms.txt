## Abstract 

Reinforcement learning (RL) has improved the ca-pabilities of large language models (LLMs) across a wide range of tasks. However, token-level RL assigns an action’s advantage to the entire gen-erated response, including tokens specifying the parsed action, reasoning chains, and malformed content. Although the environment executes only the parsed action, variation in how the action is expressed in natural language can introduce ad-ditional variance into policy-gradient estimates. We propose RLiD (Reinforcement Learning inthe Decision plane), a framework that directly optimizes the probabilities of executable action options. RLiD compiles observations, an optional compact memory, and a labeled action menu into the model input, and uses a large decision model (LDM ) to select an action in a single forward pass. By eliminating autoregressive token generation and bypassing action parsing, RLiD avoids invalid action outputs and improves RL rollout efficiency. Our analysis shows that, within a fixed text pol-icy, marginalizing over alternative realizations of the same action removes a zero-mean gradient component without changing the expected update. We further distill trained LDM policies into gen-erative LLMs through supervision on their action trajectories. Experiments on ARC, Countdown, and Sokoban demonstrate improved performance or lower computational cost across several set-tings. On ALFWorld, the complete training and distillation pipeline reaches 99.3% success in 12.7 H100 GPU-hours, compared with 86.6% in 17.3 GPU-hours for token-level RL of the same LLM. With compiled memory, our strongest Qwen2.5-1.5B LDM and distilled generative LLM achieve 100% success on all 134 unseen and 140 seen ALFWorld evaluation games.

## 1. Introduction 

Reinforcement learning (RL) has improved the capabilities of large language models (LLMs) in reasoning and interac-tive decision-making tasks (Shao et al., 2024; Wang et al., 2025; Feng et al., 2025). For language agents, RL typically operates in the token plane . The model generates a response, often a rationale followed by an action command, and the action’s advantage is assigned to every generated token. However, the environment executes only the parsed action, while training also updates reasoning chains, formatting to-kens, and potentially malformed content. Different natural-language responses can specify the same action yet produce different policy-gradient estimates. This variation can in-troduce additional gradient variance without changing the executed decision. Autoregressive generation also adds roll-out cost, and unparseable outputs can waste interactions. These observations motivate directly optimizing the proba-bilities of executable action options. We propose RLiD (Reinforcement Learning in the Deci-sion Plane) for tasks with a finite menu of available actions, such as admissible commands, grid-world moves, or answer options. A compiler prepares the observation, an optional compact memory from past feedback, and a labeled action menu. A large decision model ( LDM ) reads this input in one forward pass and outputs a categorical distribution over menu labels (Chen et al., 2026a). Existing RL objectives then optimize the selected actions’ probabilities. This for-mulation eliminates autoregressive token generation during rollouts and bypasses action parsing, ensuring that every selected action belongs to the executable menu (Figure 1). Our analysis relates text-level and decision-level credit. When reward depends on text only through the parsed action, the whole-string score decomposes into the induced action score and a zero-mean realization score. Within the same text policy, marginalizing over alternative expressions pre-serves the expected update and removes the associated vari-ance component (Proposition 1). An LDM models actions directly and has no text-realization component. Temporal credit assignment still requires estimators such as GiGPO (Feng et al., 2025). Making the decision plane trainable. Four issues recur across environments, each with a simple decision-level fix (Appendix D). (i) Label bias: pretrained models prefer some labels regardless of content (Zheng et al., 2024), and RL can amplify this into collapse onto one label. We shuffle menus during training. We either add a penalty KL( u ∥ ¯πk)

between the uniform distribution and the mean label dis-tribution of each micro-batch, per menu size (Sokoban, Qwen2.5 runs on Countdown and FrozenLake), or subtract a calibration βk that receives no gradient and is updated after each iteration from the observed label marginal (ALF-World, Qwen3.5 runs on Countdown and FrozenLake); the penalty works better on small fixed menus, the calibration on menus whose size varies (Appendix D). (ii) Length weight-ing (ALFWorld; Qwen3.5 Countdown runs): each decision is weighted by ¯T /T (i), changing the surrogate so that every episode carries equal total weight. (iii) Anchors: the GiGPO anchor key excludes path-dependent memory, which would make almost every state unique. (iv) Evaluation: greedy decoding can loop, so we also report sampled ( T =1 ) evalu-ation. 

Distill + RL. Teacher choices in successful rollouts super-vise another LDM on freshly shuffled menus, followed by decision-level RL. They also supervise a generative LLM on action strings, transferring the policy back to the token plane (Section 6). 

## 3. Experimental Setup 

Environments. We use five environments with differ-ent credit-assignment structure (Appendix Table 8). ARC-Challenge (Clark et al., 2018) is a one-step bandit: 1,119 training, 299 validation and 1,172 test questions, with the answer options as the menu. Countdown (Pan et al., 2025) requires combining 3–4 numbers with arithmetic to hit a target in up to three reductions. Its menu of “slot i op slot 

j” reductions was written once by a frontier model (gpt-6-3RLiD: Reinforcement Learning in the Decision Plane 

astra) from a task description and audited. The afterstate variant additionally shows each reduction’s result and the re-maining numbers. We use 100k training and 1,024 held-out problems. Sokoban (6 ×6, one box) and FrozenLake (4 ×4, slippery; slips are seeded per task, so the episodes of a group share slip randomness, unlike the credit audit) follow the RAGEN protocol (Wang et al., 2025): at most 10 ac-tions, four moves, 512 test seeds and 512 out-of-distribution seeds (Sokoban 8 ×8 with two boxes; FrozenLake 6 ×6). 

ALFWorld (Shridhar et al., 2021) has 50-step household tasks with admissible commands as the menu. We follow the GiGPO protocol (Feng et al., 2025): 134 unseen and 140 seen evaluation games. Its compiled memory tracks location, held object, contents of visited receptacles, unvis-ited receptacles and completed operations, computed from textual feedback only. 

Models and training. Backbones are Qwen2.5-Instruct (0.5B, 1.5B, 3B, 7B) (Qwen Team, 2025) and Qwen3.5 (2B, 4B, 9B) (Qwen Team, 2026), each with LoRA rank 16 on all linear layers of the language model. An iteration samples 16 tasks with G=8 episodes each (ARC: 64 ques-tions; Countdown-after: 32 problems), so groups are formed per task. Sequential environments use GiGPO advantages, ARC uses GRPO. Updates are PPO-clip(0.2) with AdamW and four to 24 minibatches per iteration. Learning rates (1e-5 to 1e-4) were chosen per backbone on validation data. Checkpoints are selected on a validation split: ARC’s own, otherwise 256 held-out training tasks. The test split is also logged every 10–25 iterations for learning curves, which permits adaptive peeking during development. We therefore report the final checkpoint (Countdown-after: a common matched budget), not the best test point, and list validation-selected results in the appendix. Appendix G lists every run.

## 5. An Exact Credit Audit 

How accurate is the credit that a decision-plane update ap-plies, and how does the token plane compare? On Frozen-Lake (4 ×4, slippery, 10 steps) dynamic programming makes the decision-plane audit exact; token-plane quantities are estimated. 

Protocol. Prompts are history-free (map, cell, menu), so the policy is Markov in (map, cell). For 16 held-out maps, dynamic programming over all cells and remaining horizons 

h ≤ 10 gives the exact advantage Aπh (s, a ) and objective 

J (mean success probability), and, for the LDM , the exact policy gradient g⋆ in one backward pass. From independent batches of G=8 episodes per map (about 800 decisions) we form sampled gradients with GRPO, GiGPO and exact (“oracle”) advantages. We report their cosine to the refer-ence gradient, sign agreement with exact advantages, and the improvement ∆J after one SGD step scaled to a mean decision-distribution KL of 0.01. In the token plane the semantic policy is estimated from 32 completions per cell. Appendix J gives all details. 

Where credit lands. With exact advantages, a single batch of about 800 sampled decisions gives a decision-plane gra-dient whose cosine with the exact policy gradient is 0.88. Every one of the 32 steps improves the exact objective, by 

9.9 ± 0.6×10 −3 on average at KL 0.01. With exact ad-vantages, the aggregate update is thus well aligned and im-proving in every audited trial; the remaining misalignment reflects sampling noise over which decisions were visited. In the token plane a large share of each update acts else-where: on fixed probe texts, only 61%–63% (answer only) and 0.3%–0.3% (30-word rationale) of an update’s absolute log-probability change falls on the answer-label token, and per-step improvements have smaller point estimates with greater estimation uncertainty; the rationale comparisons are inconclusive (Table 4; Appendix J). This is descriptive. The quantity Proposition 1 speaks about is measured next. 

Realisation variance. Proposition 1 predicts how much of the token-plane score is noise about how the action was writ-ten. For each of 24 FrozenLake cells we sample 48 comple-tions and compute each completion’s score ∇ log p(y | x).Grouping completions by outcome class (parsed label or invalid), the law of total variance splits the score’s second moment into a decision part E∥∇ log π(c | x)∥2 and a reali-sation part E∥∇ log p(y | x, c )∥2. We estimate within-class variances with nc − 1 denominators and count classes with a single completion entirely as decision variance, which lowers the expected realisation numerator (not a guaranteed bound on each pooled ratio). ## 7. Related Work 

Language models as policies over admissible actions. 

SayCan (Ahn et al., 2022) scores actions without RL on the language model. GLAM (Carta et al., 2023) and TWO-SOME (Tan et al., 2024) fine-tune language models with online RL over admissible actions., scoring each action string by token likelihood; we read one categorical from a single prefill. Verbalised action masking (Zhang et al., 2026) and POAD (Wen et al., 2024) keep generation and token credit. Large decision models (Chen et al., 2026a) and other supervised single-token readouts (TypeSafe, 2026; Bespoke Labs, 2026; Dai et al., 2026; OpenJev authors, 2026), con-strained decoding and policy distillation also exist; RLiD adds the credit identity, controlled RL comparisons, an exact audit and distillation in both directions. 

RL for language agents and credit. Group-baseline to-ken RL (Shao et al., 2024) extends to agents in RAGEN (Wang et al., 2025), ArCHer (Zhou et al., 2024) and GiGPO (Feng et al., 2025), whose decision-level anchor advantages we reuse; DARS (Chen et al., 2026b) shapes step credit by task dependencies. Proposition 1 is a Rao–Blackwell argu-ment for score-function estimators (Williams, 1992; Sutton et al., 2000). 

## 8. Conclusion 

RLiD gives RL one prefill per decision, no realisation noise and no invalid outputs. Its policies distil back into ordi-nary generative LLMs that act without an admissible menu, hold their success under sampling and are reached at lower measured cost than token-level RL, so RLiD serves the post-training of both LDM s and LLMs. 8RLiD: Reinforcement Learning in the Decision Plane

When does the independence hold? In our runner the history shown at later steps contains the executed action string and the observation, never the generated rationale. Future states, rewards and other episodes therefore depend on y only through a,and so does any advantage computed from them, including GRPO, GiGPO and oracle advantages. If rationales were fed back into later prompts, future states would depend on y beyond a, the conditional-independence assumption would fail, and the proposition would not apply without further assumptions. 

Invalid outputs and format penalties. In our token-plane runner an unparseable string executes a uniformly random action and receives a penalty. Rewards then depend on y through the outcome class c = g′(y) ∈ { 1, . . . , k } ∪ {⊥} (a parsed label, or invalid) together with an execution kernel that maps ⊥ to a random action. The proposition holds verbatim with 

a replaced by c: p(y | x) = π(c | x)p(y | x, c ), the realisation score ∇ log p(y | x, c ) has zero conditional mean, and any advantage that depends on y only through c and the execution randomness is conditionally independent of the realisation given c. The decision plane has no ⊥ class. 

Interpretation of the identity. Proposition 1 is an identity within one policy : for a fixed text policy, its own score-function gradient equals the gradient of its induced decision policy plus a zero-mean term. That term assigns the decision’s advantage to how the action was verbalised: rationale tokens, formatting, and which of several strings parse to the same action. Estimating ∇ log πθ (a | x) instead removes this output-realisation sampling noise without changing the expected update. A free-form token policy cannot do this, because its marginal over strings is intractable. An LDM (or, equivalently, generation constrained to a single legal label) parameterises πθ (a | x) directly, so the realisation term is identically zero. This does not mean that an advantage moves only the evaluated decision’s probability: parameters are shared across states, as in any policy gradient. The proposition does not compare an LDM with a token policy of different parameters: the two planes induce different policy classes (rationales add computation), and our token-plane baseline uses token-averaged PPO rather than the whole-string score. These are empirical questions, which Sections 4 and 5 address.

## F. Failure Modes by Plane 

Failure modes that only exist in the token plane. Two failure modes are specific to the token plane: unparseable outputs (86% of early Sokoban decisions with a short rationale) and credit spent on form (Section 5). 

Label bias (both planes). Label bias affects RL over labelled menus in both planes (Section 4). Pretrained backbones put content-independent mass on early letters, and RL with unshuffled menus amplifies it to near-deterministic collapse onto one label. Shuffling menus during training makes a content-driven policy’s label marginal uniform. The marginal regulariser or the calibration in Eq. (1) then removes the residual preference. On fixed four-action menus (Sokoban) the regulariser gives 38–55% with Qwen2.5-0.5B, against 17% with calibration. On variable-size menus (ALFWorld) we use calibration instead (Appendix D). ## J. Credit Audit Details 

Setting. Qwen2.5-0.5B-Instruct with a freshly initialised LoRA adapter (rank 16), i.e. the start of RL. 16 FrozenLake maps (the first 16 test seeds), 4 ×4, slip model with 80% intended move, horizon 10, reward 1 on reaching the goal, γ = 1 .Prompts contain map, current cell and the fixed canonical menu (no history, memory or step counter), so the policy is Markov in (map, cell) and exact policy evaluation applies. Batches. Each batch samples 8 episodes per map (about 730–890 decisions) with independent slip and action randomness. Advantages: GRPO (episode return minus group mean), GiGPO (plus centred return-to-go at (map, cell) anchors), and the exact Aπh (s, a ). Update and ∆J. The batch gradient (ascent direction, no clipping, entropy or regularisers) is followed by an SGD step whose size is found by a line search (up to 6 trials, starting at unit-gradient scale 0.01) so that the mean KL between old and new decision distributions over visited cells is 0.01; achieved KLs (for the token plane, the smoothed Monte Carlo estimate used for step selection, not an independently verified semantic KL) average 0.0100 (decision plane), 0.0099 (answer only) and 0.0108 (rationale). Weights are restored after each step. For the decision plane ∆J is exact. For the token plane the semantic policy is re-estimated from 32 sampled completions per cell before and after the step (paired seeds), and ∆J is computed by the same dynamic programming on the estimated policies. Token-plane reference and shares. The token reference gradient is a Monte Carlo estimate from the same 32 completions per cell with exact DP advantages of the estimated policy; because policy, advantages and reference are coupled plug-in estimates, the token-plane cosines have no guaranteed bias direction. Shards share the reference sample and evaluation seed streams (which depend on the local batch index), so reported standard errors are conditional on that shared randomness. The decision share is the fraction of the summed absolute change in token log-probabilities, over 64 fixed probe completions, that falls on the answer-label token. Runs. Decision plane: 32 batches, 166 GPU-seconds. Token, answer only: 8 batches, 3302 GPU-seconds, invalid answers 0.5%. Token, 30-word rationale: 4 batches from independent shards (different batch seeds, same policy and maps; shards merged batch-wise), invalid answers 84.2% at the start of RL. Line-search bug note: an earlier version could select a null step when no trial came close to the KL target; it was fixed before all reported runs. 

Token-plane updates in detail. In the token plane we describe where updates act. On fixed probe texts we measure how an update’s absolute change in token log-probabilities is distributed over generated tokens. This is a descriptive statistic, not 18 RLiD: Reinforcement Learning in the Decision Plane 

the realisation variance of Proposition 1, which we measure directly below. For an answer-only policy, whose outputs are almost always “ Answer: X” (0.4% invalid), 61%–63% of the change falls on the answer label under oracle advantages; the rest moves format tokens. Its mean improvement per step is 7.0 / 6.7 ×10 −3 (whole-string / token-mean score), with 1.4–1.8 times the batch-to-batch variance in ∆J of the decision plane; that variance also includes the noise of estimating the token policy. With a 30-word rationale, 84.2% of the base policy’s outputs do not parse and only 0.3%–0.3% of the change falls on the answer label. Improvements are inconclusive: 4.0 / -0.2 ×10 −3 for oracle and 2.9 / 0.0 ×10 −3 for GRPO advantages, with oracle standard errors of 1.6 / 2.0 ×10 −3 (GRPO: 0.5 / 2.7 ×10 −3). These rationale results rest on 4 batches from shards that share policy estimates. Token-plane cosines are not comparable with the decision plane’s exact ones. For invalid token outputs, the oracle advantage of the randomly executed fallback action is used, so token-plane oracle updates retain fallback-action noise.

Why token RL is slow: staying on the list. Token-level RL of the same LLM learns the output format within about four iterations (0.6 GPU-h), then spends most of its budget learning to stay on the admissible list (Table 30). Each off-list command wastes a step, episodes run to the 50-step limit, and GiGPO groups with equal returns carry no signal. In diagnostic rollouts the base model’s outputs are 96% malformed (untagged text, wrong tags or unclosed tags); after 30 iterations the format is learned, but 71% of commands are off the list, mostly repeats of a command that is no longer admissible (54%) and empty actions (29%). The LDM outputs a softmax over listed labels, so every sample is a legal action from the first iteration. With a Qwen3.5-2B backbone, which follows the format and stays mostly on the list, the LDM still reaches 76.1% at iteration 40 in 3.3 GPU-h, against 19.9% for token RL in 7.0 GPU-h.
