Abstract 

Reinforcement learning for long-horizon LLM agents faces a fundamental dilemma: success-ful experiences are essential for policy improve-ment, yet limited policy capabilities make such experiences difficult to discover. Sparse out-come rewards compound this challenge, leav-ing sampled trajectories with little relative feed-back for learning. In this paper, we propose TriGRPO, a tree-based reinforcement learning framework that turns scarce successes into ex-ploration and learning signals through hind-sight credit assignment within and across roll-out trees. TriGRPO constructs rollout trees through hindsight-guided branching: when an ongoing trajectory reaches a matched decision state, a successful action discovered during rollout initiates a sibling branch that contin-ues autonomously, enabling further exploration and parent–sibling comparisons. Three comple-mentary groups organize policy optimization over these trees: root groups capture within-prompt relative returns, node groups assign credit from parent–sibling outcome differences, and cross groups supplement sparse feedback with historical performance on related tasks. Experimental results demonstrate consistent gains in task performance and rollout efficiency across model scales, highlighting structured hindsight credit assignment as an effective ap-proach to long-horizon agent learning.

Existing approaches compare sampled trajec-tories: GRPO (Shao et al., 2024) uses within-group returns without a learned critic, while GSPO (Zheng et al., 2025) refines sequence-level opti-mization. For multi-turn agents, GiGPO derives step-level credit from recurring states (Feng et al., 2025), and Tree-GRPO compares prefix-sharing continuations (Ji et al., 2025). CAST uses game-solver values for turn-level supervision (Wang et al., 2026b); PVPO addresses degenerate groups through difficulty filtering and pre-estimated base-lines (Feng et al., 2026). Yet autonomous exploration limits the experi-arXiv:2611.02706v1 [cs.LG] 2 Nov 2026 ence available for learning. Under sparse rewards, failures can dominate sampling without providing within-group relative signals. The policy needs successful experience to improve, yet its limited capability makes that experience difficult to obtain. Occasional successes offer a foothold: repeating useful decisions enables deeper exploration (Oh et al., 2018), while replay supports further updates (Zhan et al., 2026). We seek to make scarce suc-cesses guide new interactions, helping other trajec-tories build on discovered behaviors and learn to complete tasks independently. We propose TriGRPO (Triple Group Relative Policy Optimization), a unified framework that op-erationalizes hindsight successes into multi-scale relative optimization. Rather than passive offline replay, TriGRPO exploits discovered successes strictly online along two dimensions: within-tree hindsight branching to actively guide exploration, and across-tree hindsight credit assignment to en-rich sparse learning signals. Under exact matching of sufficient decision states, our analysis shows that success-conditioned action replacement yields a nonnegative expected gain in task success proba-bility, motivating state-aligned branching at action disagreements (Figure 1). TriGRPO structures multi-scale credit assign-ment around three comparison groups derived from this hindsight mechanism. At the prompt level, standard unguided rollouts form a root group eval-uated against within-prompt returns. Within each tree, when an ongoing rollout reaches an observ-able state previously visited by a completed suc-cessful trajectory, a new branch splits off by exe-cuting the corresponding hindsight action and con-tinues autonomously, forming a node group; this branched trajectory receives only node credit from parent–sibling outcome differences. Across trees, unguided rollouts reference related tasks’ historical performance to form a cross group without gen-erating additional rollouts, receiving cross credit against this historical benchmark. Injected actions are supervised solely with behavior cloning, while autonomous decisions are optimized via reinforce-ment learning with their corresponding credits. No external demonstrations or preliminary sampling are required. Our contributions are summarized as follows: • We establish a theoretical guarantee that success-conditioned action replacement yields nonnegative expected gains, which motivates an online hindsight-branching strategy requir-ing no offline replay, external demonstrations, or auxiliary sampling overhead. • We propose TriGRPO , a unified framework that translates hindsight experience into com-plementary policy optimization signals across three comparison groups: root groups for within-prompt relative credit, node groups for branch-level credit, and cross groups for his-torical feedback across related tasks. • Extensive experiments demonstrate that Tri-GRPO improves success rates by up to 6.2% over state-of-the-art baselines while reducing rollout token consumption by up to 39.4%. 

2 Related Work 

Group-Based Policy Optimization and Credit Assignment. GRPO (Shao et al., 2024) replaces the learned critic in PPO (Schulman et al., 2017) with group-relative baselines, while variants such as DAPO (Yu et al., 2025), Dr. GRPO (Liu et al., 2025), and GSPO (Zheng et al., 2025) improve op-timization stability. Other studies leverage reward variance or auxiliary rollouts to reshape feedback (Jiang et al., 2025, 2026; Feng et al., 2026). For step-level credit, GiGPO (Feng et al., 2025) clus-ters naturally recurring anchor states, and CAST (Wang et al., 2026b) relies on external solver values. In contrast, TriGRPO requires no external solvers; it couples a cross-batch historical baseline with lo-calized parent–sibling counterfactual comparisons at matched decision states. 

Tree-Based Rollouts and Exploration. Tree topologies support both inference planning (Yao et al., 2023; Zhou et al., 2024) and policy optimiza-tion. TreeRL (Hou et al., 2025) and Tree-GRPO (Ji et al., 2025) employ tree rollouts with prefix sharing and hierarchical advantage estimation. Un-like Tree-GRPO’s unguided random expansion, Tri-GRPO initiates branches deterministically when an active rollout matches a state banked by a suc-cessful trajectory from the same prompt, concen-trating compute where verified alternative actions are known. We evaluate against GiGPO and Tree-GRPO as our primary baselines for step-level credit and tree exploration, respectively. 

Hindsight and Experience Reuse. Hindsight learning extracts training signals from past roll-outs (Andrychowicz et al., 2017). In LLMs, ECHO (Hu et al., 2025) and HSL (Li et al., 2026) per-form post-hoc goal relabeling to construct synthetic demonstrations, while SIL (Oh et al., 2018) and ExGRPO (Zhan et al., 2026) replay prioritized suc-cesses. Rather than altering goals or replaying offline trajectories, TriGRPO applies hindsight on-line at the action level, injecting verified actions into concurrent rollouts to compute counterfactual policy-gradient advantages in real time. 

3 Method 

3.1 Preliminaries 

We consider a multi-turn agent interacting with an environment to accomplish a task specified by a prompt x. At each step t, the agent receives an observation ot and selects an action at according to a policy πθ(· | ht), where ht = ( x, o 1, a 1, . . . , o t)

denotes the interaction history. This process gen-erates a trajectory τ = ( o1, a 1, . . . , o T , a T ) un-til termination, with a binary outcome reward 

R(τ ) ∈ { 0, 1} indicating task success or failure. For each prompt x we sample a group of N trajec-tories, Gx = {τi}Ni=1 .

3.3 TriGRPO 

Building on Section 3.2, we propose TriGRPO, in-tegrating three components: (i) prefix-sharing tree rollouts, (ii) hindsight branching guided by success-ful actions, and (iii) hindsight credit assignment through root-, cross-, and node-level advantages. 

Tree-structured rollouts. Rather than sampling 

N trajectories independently for each prompt x,we generate R root trajectories and expand sam-pled non-leaf nodes into prefix-sharing trees (Ji et al., 2025). We denote by Gx the set of all gen-erated trajectories (root and branch) for prompt 

x. Prefix sharing eliminates redundant generation and enables comparisons at multiple levels of the trajectory hierarchy. 

Hindsight Branching. Following Eqs. (3) and (6), TriGRPO maintains a dynamic success bank B of successful trajectories with R(τ ) = 1 

from the current prompt. When an active trajectory 

τi reaches a decision state s that matches a state 

s′ visited by a trajectory in B, and the two actions disagree ( a+̸ = ai, where ai is the action τi

would have taken at s), we spawn a counterfactual sibling branch τj that inherits τi’s prefix up to 

s, substitutes the banked action a+ ∈ B, and continues autonomously under πθ. We denote unguided trajectories by U and guided branches by 

V; each pair (τi, τ j ) forms a node group isolating the causal effect of the action at s (Figure 2).

4 Experimental Results 

4.1 Setup 

Experiments are conducted on two interactive benchmarks: ALFWorld (Shridhar et al., 2021) (n=128 test tasks) and SearchQA (Jin et al., 2025) (51,713 test questions spanning 7 benchmarks). We report the peak validation success rate (SR) aver-aged over 3 random seeds, alongside cumulative token consumption up to the peak step to quantify sampling efficiency. Detailed environment configu-rations are provided in Appendix A.1 and A.3. We compare against: (1) GRPO (root-only), (2) Tree-GRPO (Ji et al., 2025), (3) GiGPO (Feng et al., 2025), and (4) GSPO (Zheng et al., 2025). All baselines share the training configuration and evaluation protocol above; reproduction details are in Appendix A.4. Unless otherwise noted, all runs use a learning rate of 1 × 10 −6 with a constant schedule. On ALFWorld the tree rollout uses R=8 root trajec-tories per prompt with up to L=12 leaves and a training batch of 16 prompts per step for 150 steps; on SearchQA the budget is reduced to R=3 roots with up to L=5 leaves and a batch of 256 prompts per step. Complete hyperparameters are in Ap-pendix A.2.

4.4 Ablation Study 

We conduct three complementary ablations on ALFWorld with Qwen2.5-3B-Instruct: a compo-nent ablation that removes or replaces individ-ual terms of the three-level advantage estimator, a prefix-credit ablation that varies whether subtree credit is written into the loss of shared prefix tokens, and a cross-advantage ablation that dissects the his-torical baseline of Across . Detailed protocols and the full results of the latter two suites are provided in Appendix C; here we present the component ablation and the key findings. 

Component ablation. The full model com-bines root advantage Aroot (within-prompt group-relative), cross-sample advantage Across (across-tree hindsight baseline), and node advantage Anode 

(within-tree hindsight branch credit). We selec-tively remove or replace individual components while keeping all other configurations identical: 

root+cross (w/o node) sets wnode =0 ; root+node 

(w/o cross) sets λcross =0 ; and GiGPO+cross re-places within-tree hindsight node grouping with GiGPO’s state-prefix grouping while retaining 

Across .

Results. Table 3 summarizes the component ab-lation. The full TriGRPO achieves 93.8% peak SR. Removing Anode (root+cross) drops perfor-mance to 89.8% ( −4.0 points); removing Across 

(root+node) drops it to 81.9% ( −11 .9 points); and replacing hindsight branching with GiGPO state-prefix grouping (GiGPO+cross) yields 89.5% (−4.3 points). All tree-structured configurations nevertheless outperform root-only GRPO (72.9%) by 9.0–20.9 points, confirming that the root-level tree structure itself contributes substantially over flat GRPO sampling. 

Analysis. Two findings emerge from the compo-nent ablation. (1) Across-tree hindsight credit is the dominant contributor: the 11.9-point drop when 

λcross =0 shows that Across provides critical learn-ing signal beyond within-prompt comparisons, sus-taining informative gradients even when all rollouts for a prompt yield identical outcomes—a frequent failure mode in sparse-reward environments where GRPO’s group-relative signal vanishes. (2) Within-tree hindsight branch credit is not interchange-able with generic step-level grouping: disabling 

Anode costs 4.0 points (89.8% vs. 93.8%) and sub-stituting GiGPO’s state-prefix grouping under the same cross advantage costs 4.3 points (89.5%), in-dicating that the gain comes from hindsight-guided branching itself—counterfactual branch points at matched states—rather than from the mere pres-ence of any node-level grouping. The prefix-credit and cross-advantage ablations (findings 3–4) and the token-efficiency analysis are reported in Ap-pendix C, specifically Appendix C.2, C.3, and C.4.

5 Conclusion 

We propose TriGRPO, a tree-based policy opti-mization method that performs hindsight credit as-signment over trees via a triple-group structure. Empirical results across diverse tasks and model scales demonstrate superior performance and token efficiency, validating the effectiveness of online hindsight credit assignment. 

Limitations 

A key limitation of our approach lies in hindsight branching, which hinges on exact state matching and intermediate environment resettability. Conse-quently, extending this mechanism to continuous or irreversible domains remains challenging.

A Detailed Experimental Settings 

A.1 Environments and Tools 

All models are trained with vLLM-accelerated tree rollouts. On ALFWorld we set the vLLM GPU memory fraction to 0.55 with tensor parallelism 1; on SearchQA the GPU memory fraction is 0.5 with tensor parallelism 1. All experiments adopt the Qwen2.5-Instruct base model. Specifically, we evaluate on: • ALFWorld : Evaluated across 1.5B, 3B, and 7B scales. It consists of six household interactive task types ( pick, look, clean, heat, cool, pick-two )evaluated on the standard n = 128 test games. • SearchQA : Evaluated on 1.5B and 3B scales. It comprises 51,713 multi-hop reasoning questions aggregated across seven standard open-domain QA test sets, requiring iterative web search and multi-turn reasoning. 

A.2 Hyperparameter Settings ALFWorld. All ALFWorld runs use the follow-ing hyperparameters unless otherwise noted. The tree rollout employs R=8 root trajectories per prompt with up to L=12 maximum leaves. We set the learning rate to 1 × 10 −6 with a constant sched-ule, KL penalty coefficient β=0 .01 (low-variance estimator), and advantage clipping at 10.0. The training batch size is 16 prompts per step; the val-idation batch is 128 tasks. Maximum prompt and response lengths are 2048 and 512 tokens, respec-tively. For the across-tree hindsight advantage, we use scaling weight λcross =1 .2, EMA smoothing 

α=0 .3, and shrinkage κ=8 .0. The node-level ad-vantage weight is wnode =1 .0 with branch credit minimum gap 1.0. Within-tree hindsight branching uses an injection budget of 96, saturation threshold 0.5, divergence requirement enabled, with at most 2 branches per path and minimum branch interval 5. Behavior cloning applies weight 0.15 with a hold schedule (steps 30–100, floor 0.002). Train-ing runs for 150 steps with evaluation every 5 steps, yielding 31 validation points. 

SearchQA. On SearchQA the tree budget is re-duced to R=3 root trajectories with up to L=5 

leaves per prompt to accommodate longer retrieval-augmented contexts, and the training batch is 256 prompts per step, giving a rollout group of n=5 

trajectories per prompt at temperature t=1 .0. The environment horizon is 10 interaction steps with matching history length; maximum prompt and response lengths are 9216 and 512 tokens, respec-tively, and each retrieved observation is capped at 768 tokens. The learning rate ( 1 × 10 −6, con-stant), advantage clipping (10.0), the across-tree hindsight weights ( λcross =1 .2, α=0 .3, κ=8 .0), and the node-level weight ( wnode =1 .0) are as on ALF-World, whereas the KL coefficient is β=0 .001 un-der the same low-variance estimator and the branch credit minimum gap is lowered to 0.1. Within-tree hindsight branching keeps the injection budget of 96 and at most 2 branches per path, with the satu-ration threshold at 1.0, the divergence requirement disabled, and the minimum branch interval reduced to 1; the behavior cloning schedule (weight 0.15, steps 30–100, floor 0.002) is unchanged. Training follows a one-epoch budget of 663 update steps, with checkpoints selected by periodic validation every 10 steps on a fixed set of 400 multi-hop ques-tions (100 per multi-hop benchmark, seed 42) and training stopped at the validation peak. 

A.3 Evaluation Protocols Multi-Seed Validation. To ensure statistical ro-bustness, all training runs are repeated across three independent random seeds. We record the peak validation success rate (SR) for each run and report the mean. 

Sampling Efficiency Metric. We track cumu-lative token consumption up to the training step where the policy attains its peak validation SR. This reflects the token and compute budget required to reach optimal performance. 

ALFWorld. We report peak validation success rate (SR) over the 31 evaluation checkpoints, mea-sured on the ALFWorld test split ( n=128 ) with temperature t=0 .4 and sampling enabled. Per-type SR is reported for descriptive analysis; due to small per-type sample sizes (5–29), we do not perform statistical inference on individual task categories. We additionally report cumulative token consump-tion ( total_num_tokens ) up to the peak step as a measure of sampling efficiency. 

SearchQA. Periodic validation is used only for checkpoint selection. Every reported SearchQA number comes from a separate full evaluation of the selected checkpoint: greedy decoding with an environment horizon of 10 steps on the complete test split of each benchmark (51,713 questions in total across the seven benchmarks). 

A.4 Baseline Reproduction 

All baselines are trained from the same Qwen2.5-Instruct checkpoints under the identical configura-tion and evaluation protocol described above (same rollout budget, decoding settings, and step count), so observed differences reflect the optimization ob-jective rather than baseline-specific tuning.

C Ablation Details 

C.1 Component Ablation Groups 

• root + cross (w/o node): Sets wnode =0 , dis-abling within-tree hindsight branch credit. Un-guided trajectories still receive both root and cross advantages; hindsight branches con-tribute only through behavior cloning. • root + node (w/o cross): Sets λcross =0 ,removing the across-tree hindsight base-line. Trajectories receive root advantage plus within-tree hindsight branch credit, but with-out difficulty-normalized correction from past performance on related tasks. • GiGPO + cross : Replaces TriGRPO’s within-tree hindsight node grouping with GiGPO’s state-prefix grouping, while retain-ing the same across-tree hindsight advantage (λcross =1 .2). This tests whether the node-level signal requires hindsight branching or can be achieved through alternative step-level grouping mechanisms. 

C.2 Prefix-Credit Ablation 

By default, TriGRPO enforces a credit-isolation invariant: only node-level credit enters the PPO/-GRPO policy loss, and it multiplies exclusively the tokens (actions) added after the branch point of the corresponding child; shared prefix tokens preceding the branch point neither gain nor lose gradient from the quality of the child branches, and subtree returns are never back-propagated or aggregated into ancestor or root advantages. We ab-late this design with three variants that additionally write subtree credit into the loss of shared prefix tokens: (i) mean aggregation , which injects the average performance of on-policy continuations sampled from the prefix under the current policy; (ii) max aggregation , which injects the best con-tinuation observed from that prefix, asking whether an exceptionally good completion ever existed; and (iii) shuffle , a control that permutes the real per-prefix credits already computed within the current batch without replacement, preserving their mean, variance, extremes, and total gradient scale while breaking the correspondence between each credit and its prefix. Table 4 reports the prefix-credit ablation: writing subtree credit into shared prefix tokens degrades the full model from 93.8% to 88.3% under mean aggregation, to 88.3% under max aggregation, and to 87.5% under the shuffle control. (3) Injecting subtree credit into shared prefixes is harmful, and the harm is neither a scaling artifact nor a con-tent artifact. All three variants that violate the credit-isolation invariant degrade the full model substantially (mean aggregation 88.3%, max ag-gregation 88.3%, shuffle 87.5%, vs. 93.8%), and the three remain within 0.8 points of one another. The shuffle control is diagnostic: it preserves the mean, variance, extremes, and total gradient scale of the injected credits while destroying only their correspondence to the originating prefixes, yet it degrades performance just as much as the faith-ful mean variant—so the damage stems from the act of charging shared prefix tokens for the quality of downstream subtrees, not from a mismatched credit scale. The max variant is diagnostic in the or-thogonal direction: it injects the strongest possible positive signal (the best continuation ever observed from each prefix, an upper-biased version of the mean credit), yet it fails to beat mean aggregation, so the harm is not attributable to the pessimistic content of the injected signal either. Notably, the existence of an exceptionally good continuation from a prefix—the question the max variant was designed to answer—carries no exploitable learn-ing signal once written into the prefix tokens. This supports TriGRPO’s default credit isolation: pre-fix tokens receive only the outcome credit of their own rows, while branch credit acts exclusively on tokens generated after the branch point.

The two-level structure is likewise justified—removing the coarse task-type prior ( κ=0 , −3.2 points) and removing the fine per-task EMA (coarse-only, 

−2.4 points) both degrade performance. The fine baseline captures task-specific difficulty while the coarse prior supplies a stable fallback when fine-grained samples are scarce, and their shrinkage combination is strictly better than either compo-nent alone. 

C.4 Token Efficiency 

Tree-structured configurations consume 0.249– 0.338B tokens (full TriGRPO 0.338B; root+node 0.249B), whereas the flat-sampling alterna-tives require 0.403B (GRPO) and 0.459B (GiGPO+cross)—a token reduction of roughly 16– 38% for tree rollouts. Within the prefix-credit abla-tion, the mean (0.292B) and shuffle (0.325B) vari-ants are cheaper than the full model yet perform 5.5 and 6.3 points worse, while the max variant is the most expensive configuration of the entire study (0.389B, above even the full model’s 0.338B) and still scores 5.5 points lower—showing that vi-olating credit isolation buys neither accuracy nor sampling efficiency. The same holds for the cross-advantage baseline: the default α=0 .3, κ =8 con-figuration is also the most token-efficient (0.338B), whereas every ablated variant consumes more to-kens (0.375–0.417B) yet scores lower, making the default cross configuration Pareto-optimal on both success rate and sampling cost.

Multi-turn variants. Both tasks are multi-turn. At the first turn there is no history yet, so a no-history template is used (Figures 4 and 5); from the second turn onward the prompt is augmented with the recent interaction history (Figures 6 and 7). Hindsight-branch prompt. The only TriGRPO-specific change to the model input occurs on hind-sight branches, and only at their first turn. To seed such a branch with a previously successful action, one successful action is injected into the generation prompt, as illustrated in Figure 8. The observation content itself (task, observation, ad-missible actions/queries) is left unchanged, and no answer, reward, or future observation is ever in-jected. The injected action span is subsequently relocated to the response side and supervised only by the behavior-cloning (BC) loss; the remaining turns of the branch are generated autonomously. Unguided rollouts, as well as all baseline roll-outs, never receive this prefix.

# verl/trainer/ppo/core_algos.py -- identical structure for ALFWorld and QA def ema_baseline(R, fine_key, coarse_key, state, cfg): # blend a per-task EMA (fine) with a per-task-type EMA (coarse) by shrinkage; # cold start falls back to whichever EMA exists, else 0 mu_f = state.mu_fine.get(fine_key) # None on first occurrence mu_c = state.mu_coarse.get(coarse_key) if mu_f is None and mu_c is None: return zeros_like(R) if mu_f is None: return mu_c if mu_c is None: return mu_f n = state.count_fine.get(fine_key, 0) # #root trajectories seen (fine) return (n * mu_f + cfg.kappa * mu_c) / (n + cfg.kappa) # kappa = 8 def update_ema(R, fine_key, coarse_key, state, alpha): # alpha = 0.3 # updated AFTER this step's advantages are computed (preserves causality) m = R.mean() state.mu_fine[fine_key] = ema(state.mu_fine.get(fine_key), m, alpha) state.mu_coarse[coarse_key] = ema(state.mu_coarse.get(coarse_key), m, alpha) state.count_fine[fine_key] = state.count_fine.get(fine_key, 0) + 1 # ema(old, new, alpha) = alpha * new + (1 - alpha) * old (first step: = new) def compute_hindsight_tree_advantage(batch, cfg): R = batch.returns # (1) ROOT : GRPO over the unguided trajectories of the same prompt A_root = group_relative(R, group=batch.uid) # (2) NODE : outcome difference within each 2-member node group # (the parent trajectory + the guided branch cloned from its state) A_node = batch.R_branch - batch.R_parent # no variance normalization # (3) CROSS: deviation of the return from a historical baseline A_cross = (R - ema_baseline(R, batch.fine_key, batch.coarse_key, batch.state, cfg)) / cfg.sigma_r return where(batch.tree_guided, cfg.lambda_node * A_node, A_root + cfg.lambda_cross * A_cross)
