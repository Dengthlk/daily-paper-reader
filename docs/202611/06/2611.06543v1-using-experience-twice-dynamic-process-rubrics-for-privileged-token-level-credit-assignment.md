## 摘要
智能体轨迹通常同时包含成功决策与失败尝试，但基于稀疏轨迹级奖励的优化难以识别哪些关键决策应被强化或抑制。我们观察到，同策略轨迹之间的有意义差异可以被提炼为自然语言过程评分细则，并用作过程监督信号。基于这一洞察，我们提出在线评分细则自蒸馏（ORSD），利用自生成的过程评分细则进行稠密 token 级监督，从而增强以结果为中心的强化学习。具体而言，当前策略在每个步骤根据同一组轨迹独立生成多个评分细则包，从跨轨迹的行为差异中提取候选过程评分细则。随后，一个冻结的验证器针对组内每条轨迹评估所有评分细则项，并基于评分细则满足情况与任务成功之间的包级对齐程度选择一个候选评分细则包。ORSD 在训练期间将选中的评分细则包视为特权信息，然后比较原始 token 在带评分细则与不带评分细则条件下的对数似然。由此得到的似然差提供 token 特定的过程信用，并通过加性优势塑形将其加到原始轨迹级 GRPO 优势上。因此，ORSD 连接了轨迹级结果监督与细粒度过程监督，使得能够利用过程信号进行 token 级信用分配。在 ALFWorld 和 WebShop 上的大量实验表明，在相同环境交互预算下，ORSD 对 Qwen3-1.7B 和 Qwen3-4B 均能加速策略改进并提升最终任务性能。代码见 https://github.com/AnnaXChun/ORSD。

## Abstract
Agent trajectories often contain both successful decisions and failed attempts, yet optimization with sparse trajectory-level rewards struggles to identify which critical decisions should be reinforced or suppressed. We observe that meaningful distinctions among on-policy trajectories can be distilled into natural-language process rubrics and used as process supervision signals. Based on this insight, we propose Online Rubric Self-Distillation (ORSD), which leverages self-derived process rubrics for dense token-level supervision, thereby augmenting outcome-centric reinforcement learning. Specifically, the current policy independently generates multiple rubric bundles at each step according to the same group of trajectories, extracting candidate process rubrics from cross-trajectory behavioral differences. A frozen verifier then evaluates all rubric items against each trajectory in the group, and selects one candidate bundle based on bundle-level alignment between rubric satisfaction and task success. ORSD treats the selected rubric bundle as privileged information during training, then compares the log-likelihoods of the original tokens with and without the rubric. The resulting likelihood gap provides token-specific process credit, which is added to the original trajectory-level GRPO advantage through additive advantage shaping. ORSD thus bridges trajectory-level outcome supervision and fine-grained process supervision, enabling token-level credit assignment using process signals. Extensive experiments on ALFWorld and WebShop show that ORSD accelerates policy improvement and boosts final task performance for both Qwen3-1.7B and Qwen3-4B under the same environment-interaction budget. Our code is available at https://github.com/AnnaXChun/ORSD.

## 1. 核心问题与研究动机

- **背景**：LLM 智能体需在 ALFWorld、WebShop 等长程交互环境中规划动作、探索并纠错。RLVR（带可验证奖励的强化学习）与 GRPO 已成为主流训练范式，但奖励通常是**轨迹级稀疏信号**。
- **核心痛点**：在 GRPO 下，一条轨迹内**所有 token 共享同一优势值**，导致有用决策、冗余步骤、可恢复错误获得相同学习信号，无法定位"哪些关键决策应被强化或抑制"。
- **已有工作的不足**：
  - GiGPO 通过状态匹配做 **step 级**优势估计，但同一动作内 token 仍共享信号；
  - Rubrics as Rewards、RLCF、OpenRubrics、Rubrics to Tokens 等评分细则方法虽引入更丰富的评价标准，但反馈多停留在**轨迹级**，且细则多为**离线预先生成、训练中固定不变**，无法随策略演化更新。
- **核心洞察**：同策略轨迹组之间的行为差异可被提炼为**自然语言过程评分细则**；比较"有/无细则"两种上下文下同一 token 的对数似然差，即可把细则转化为 **token 级过程信用**。这构成"经验两次利用"（同批 rollout 既用于生成细则，又用于特权配对重放），无需额外环境交互。

## 2. 方法论（ORSD：在线评分细则自蒸馏）

- **总体流程**（每训练步）：
  1. 对任务 x 用 π_old 采样 N=8 条轨迹，按组内归一化得 GRPO 优势 A_GRPO；
  2. **在线细则生成**：以任务描述 + 整组轨迹 + 生成指令为输入，由当前策略独立采样 M=4 个候选细则包（每包 5–8 条可观测过程准则）；生成时**不输入结果奖励**，以防细则退化为结果奖励的简单复述；
  3. **细则—奖励对齐筛选**：冻结验证器（Qwen3.5-Plus，temperature=0、关闭思考、JSON 输出）对每条轨迹的每条准则打分 S∈[0,1]，包内平均得满足度 s_i^(m)；计算 s 与奖励 r 在组内的 **Spearman 相关 ρ^(m)**，取最大者为 B*；
  4. **特权配对重放**：对每个策略生成的 token y_{i,ℓ}，分别计算 log π_old(y|x, B*, y_<ℓ) 与 log π_old(y|x, y_<ℓ)，差值 Δ_{i,ℓ} 作为 token 级信用（环境观测 token 被掩码，不参与）；
  5. **加性优势塑形**：A_token = A_GRPO + α·Δ_{i,ℓ}，默认 α=0.01；正值提升该 token 优势，负值抑制；
  6. 用带裁剪的重要性采样目标（ε_c=0.2）加 KL 正则（η=1e-3）优化策略。
- **关键设计细节**：
  - 两次前向均对**同一批已采样轨迹**计算，不新增采样、不新增环境交互；
  - Δ 施加 **stop-gradient**，仅进入 A_token，不构造额外 KL 或交叉熵蒸馏损失；
  - 实现层面有 token 对齐掩码 e_{i,ℓ}（分词往返成功、似然有限才生效），失效 token 保留原 GRPO 优势；
  - 理论上该修正可同时改变轨迹平均优势与单个 token 的符号，尺度由 α 控制。

## 6. 主要结论与发现

- **主结果**：ORSD 在 ALFWorld overall 成功率与 WebShop 两项指标上于两个模型规模均排名第一。
  - ALFWorld：比最强基线 GRPO 高 **12.12**（1.7B）和 **3.36**（4B）个百分点；
  - WebShop：成功率比最强基线高 **2.80**（1.7B，vs GiGPO）和 **10.90**（4B，vs GRPO）个百分点，score 同步提升。
- **在线 vs 离线细则**：Offline Rubric 虽优于 GRPO，但比在线 ORSD 低 **4.80** 个百分点，说明细则需随策略行为与失败模式刷新。
- **对齐筛选有效**：完整 ORSD 比单包无筛选变体高 2.15 / 9.45 点（1.7B / 4B）；在候选数相同下比随机选包高 3.40 / 7.15 点。
- **α 敏感性**：三个取值均优于 GRPO，α=0.01 最优（63.00% vs 55.40%）。
- **训练动态**：四组设置下 ORSD 最终 300 步平均奖励均高于 GRPO，部分设置收敛更快，且未增加环境交互。
- **定性观察**：被选中的细则更具体（含明确属性与价格约束），被拒细则更泛化，说明对齐筛选倾向选出信息量更高的特权上下文。

## 7. 优点

- **"经验两次利用"的效率设计**：同一批 rollout 同时用于细则生成与特权配对重放，零额外环境交互、零额外采样，训练开销主要是两次前向与验证器调用，性价比高。
- **在线自适应监督**：细则由当前策略从自身轨迹差异中提炼，能跟踪策略演化中的新失败模式，克服静态 rubric 的滞后性。
- **质量筛选机制巧妙**：用"细则满足度 vs 结果奖励"的 Spearman 相关做包级选择，无需人工标注即可过滤低价值细则；生成时不喂奖励，避免退化为结果奖励的复述。
- **与 GRPO 正交兼容**：以加性优势塑形方式接入，保留原 RL 目标稳定性，实现简单、易复现（已开源）。
- **实验对照较严谨**：GRPO 基线严格同配置，同交互预算比较，并同时报告 score 与 success 两类指标。
- **理论补充清晰**：附录给出 token 修正对轨迹平均优势的影响形式与 stop-gradient 下的梯度表达，说明该方法本质是"通过优势塑形实现特权自蒸馏"，而非引入辅助蒸馏损失。

## 8. 不足与局限

- **细则知识不累积**：每步重新生成、不维护跨更新/跨任务的细则记忆库，重复发现成本高，无法形成累积过程知识（作者亦自认）。
- **选择目标与信用分配目标不完全一致**：以轨迹级相关性选包，优化的是"区分好坏轨迹"的能力，而非"在轨迹内部正确分配信用"的能力；Δ 只反映策略对上下文的响应强度，**不保证 token 正确性**。
- **外部验证器依赖**：冻结验证器为闭源 API，带来成本、延迟、可复现性与评分噪声风险；论文未报告验证器调用开销与失败率。
- **校正强度保守**：默认 α=0.01 很小，Δ 的作用幅度有限；α 调优仅在 1.7B 上验证，泛化性未知。
- **实验覆盖缺口**：消融仅在 WebShop；未与同类 token 级方法直接对比；缺少方差/显著性统计；部分基线结果引自他文，协议不完全统一。
- **子任务表现不均衡**：ALFWorld 的 Pick 子任务上 ORSD（81.25 / 83.33）未超过 GiGPO（79.20）/ 与 GRPO 持平（4B），Look、Pick2 等在 4B 上亦非全面领先，说明方法收益存在任务依赖性。
- **奖励工程引入偏差**：WebShop 训练奖励含人工设计的无效动作/循环惩罚系数，可能影响与使用原始奖励的基线之间的公平性。
- **应用限制**：需要可生成结构化细则的强策略与可靠验证器，在低资源模型或验证器不可用的封闭环境中适用性受限；长轨迹下两次前向与逐准则打分带来额外计算与工程复杂度。
