## 摘要
训练一个仅能执行上、下、左、右动作的智能体来玩 Pac-Man 引出一个基本问题：当性能不佳时，应当改进什么？困难可能来自读取屏幕，也可能来自在长序列中选择动作。我们通过独立的感知检查与原始策略强化学习研究，在基于 Qwen3.5-9B 的智能体上考察这些问题。在策略研究中，使用文本棋盘将图像转写从决策接口中移除；在选定的检查点上，八个留出迷宫上的完成率从该优化前的 0% 提高到 80.2%，并带有三条额外生命。感知检查表明，准确的静态截图读取可以与交互过程中的错误并存。另一项策略比较还表明，进一步优化可能伴随更差的动作选择。综上，这些发现促使对训练后模型进行具体检查：在使用中评估感知，区分训练成功与完整游戏验证，并考察决策及后续表现，而不是依赖单一选定分数。该研究为改进未来智能体训练与评估提供了经验教训。

## Abstract
Training an agent to play Pac-Man with only up, down, left and right actions raises a basic question: when performance is poor, what should be improved? Difficulty can arise from reading the screen or from choosing actions over a long sequence. We examine these problems in a Qwen3.5-9B-based agent through separate perception checks and primitive-policy reinforcement-learning studies. In the policy study, which uses textual boards to remove image transcription from the decision interface, completion on eight held-out mazes increased from 0% before this optimization to 80.2% at a selected checkpoint, with three extra lives. The perception checks show that accurate static screenshot reading can coexist with errors during interaction. A separate policy comparison also shows that further optimization can accompany worse action choices. Together, these findings motivate concrete checks for post-training: evaluate perception in use, distinguish training success from full-game validation, and examine decisions and later performance rather than relying on one selected score. The study provides empirical lessons for improving future agent training and evaluation.

## 1. 核心问题与研究动机

- **背景问题**：训练视觉-语言模型（VLM）智能体玩 Pac-Man 时只允许上/下/左/右四个原始动作。当最终完成率很低时，开发者面临一个归因难题：**究竟是“读不懂屏幕”（感知失败），还是“选不对动作”（长程决策失败），抑或“记忆被污染”（状态维护失败）？**
- **核心论点**：高训练胜率或某一个“最佳验证检查点”都不足以证明智能体真正变强。作者主张在把“RL 后训练成功”解读为“游戏能力提升”之前，必须先分别检查感知、记忆、决策三条证据链。
- **研究定位**：这是一篇**实证/诊断性案例研究**，而非算法论文。作者明确表示贡献在于“失败分析 + 可操作的经验教训”，不提出新 RL 目标，也不宣称技能可迁移。
- **整体含义**：小动作空间（四方向）并不降低科学难度——同一个“可走方向”可能吃到豆子、走进死走廊，或把错误推迟到很多步之后才爆发。单一完成率把这三类选择压缩成一个数字，掩盖了真正该修的模块。

## 2. 方法论：核心思想与关键技术细节

### 2.1 总体思路：解耦三条证据链
作者把 VLM 智能体功能分解为三段（附录 P.2）：

- 感知：z_t = V_θ(o_t)（读图/读棋盘）
- 状态维护：m_t = U(m_{t−1}, z_t, e_t)（harness 规则更新记忆）
- 决策：a_t = π_ϕ(o_t, m_t, C_t)（在候选动作/路线中选一个）

并刻意设计三类实验，使每类只回答一个子问题：
1. **静态感知审计**：只测“读图是否准”，不测整局胜负；
2. **ASCII 原始策略 RL**：用文本棋盘替代图像转写，隔离“读屏”变量，专测决策；
3. **固定权重 harness 因子实验 / 动作头 RL**：隔离“模型学习”与“工程 harness 改动”的贡献。

### 2.2 感知接口的关键细节
- 图像统一做 **2× 双三次放大**（16px 单元格 → 32px），目标为“每格一个视觉 token”，支持最大 25×21 棋盘。
- 严格 JSON 输出契约：整图转写 `{"rows":[25 个 21 符号串]}`；actor 查询输出 `pacman_rc` 与按行列排序的 `ghosts` 列表。
- 训练分两阶段：视觉编码器/merger 全参训练（6,000 步，lr 1e-5）→ 冻结视觉、仅语言侧 LoRA（rank 16, α=32，1,000 步，lr 1e-4）。
- 隐藏格必须标为 `?`（未知），不得用引擎真值填补——这是后续“记忆污染”诊断的接口前提。

### 2.3 ASCII 原始策略 RL（主训练轨迹）
- 观测为带空格的文本棋盘 + 声明的位置/导航历史；动作是单个方向 token。
- **开放动作掩码**：只在声明可行动作集 A_t 上做 softmax（τ=0.7）：
  π^open_θ(a|x_t) = 1{a∈A_t}·exp(ℓ_θ(a|x_t)/τ) / Σ_{b∈A_t} exp(ℓ_θ(b|x_t)/τ)
  作者强调：**“开放”不等于“安全”**，掩码只保证合法，不保证避开幽灵或保留未来路线。
- **PPO 式裁剪代理目标**（ε=0.05，KL 与熵系数为 0，启用 ClipCov）：
  r_i^t(θ)=π_θ(a_i^t|x_i^t)/π_old(a_i^t|x_i^t)
  J_clip=E[min(r·A, clip(r,1−ε,1+ε)·A)]
- **课程学习**：7 个阶段，迷宫从 13×13/2 鬼逐步扩到 21×25/4 鬼；每批 13:3 主阶段/复习阶段（18.75% 旧阶段回放）。
- **失败状态重启**：从死亡前的模拟器快照重启（回看窗口 4–7/8–15/16–32 步），每类 80% 请求重启，无合适状态则回退普通开局。
- **优势按 episode 分组**（而非把不同决策的中间回报混池）：作者给出算术示例说明混池会把一个未变动作的优势从 +0.17 翻到 −1.26。

### 2.4 Harness 层方法（Route-option）
- 选项分三类：Collect（吃豆并保留退路）、Avoid（撤到多出口路口）、Eliminate（追可吃幽灵）；模型输出的是**随状态变化的单字母代码**，而非固定方向。
- **有界风险检查**：估计幽灵能否在有限步内先到该路线，用于排序/过滤候选。
- **路线绑定**：选定后连续执行多步，直到完成或中断；与“目标重规划”构成 2×2 因子设计（B0/B1 × S0/S1）。
- 动作头 RL：只训练 rank-8、α=8 的输出残差（约 201.9 万 FP32 参数），基础模型、感知、harness 全部冻结。

## 6. 主要结论与发现

1. **确实存在可测的提升，但不稳定**：8 张留出图上 checkpoint 0 → 270 从 0/96 升到 77/96（80.2%）；峰值 335 为 78/96；但最后一次完整验证 425 回落到 60/96。作者拒绝把它称为“稳定保持”或“泛化”。
2. **训练胜率会系统性高估进度**：原始分支 batch 333 达 192/192 全胜，但其中 132 次是 T7 重启，**96/132 开局只剩 ≤15 颗豆（48 次只剩 1 颗）**，且来自仅 11 个重启状态、2 张地图、3 个源 episode。重启状态库 50 次更新内 100% 换新，但每次只覆盖 2–5 张图、4–12 个源 episode——**状态新颖 ≠ 来源多样**。
