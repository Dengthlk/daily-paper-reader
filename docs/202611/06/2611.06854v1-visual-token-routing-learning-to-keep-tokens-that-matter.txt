## Abstract 

Computer-use agents (CUAs) have recently achieved superhuman performance on several long-horizon benchmarks. However, their computational cost limits their use in long-horizon tasks and real-time domains such as video games. A key bottleneck is representing each screenshot as thousands of visual tokens, which accumulate into long contexts as agents reason over extended interaction histo-ries. We observe that most of these visual tokens are either semantically irrelevant to the agent’s next action or temporally redundant across screenshots. Building on this observation, we introduce Visual Token Routing (VTR), a joint training framework for learning sparse visual representations that preserve the information needed for action prediction. In VTR, we train the vision-language model together with a lightweight spatio-temporal router that examines each image region in the current and previous screenshots and decides whether its visual token enters the language model. We optimize the router using an adaptive loss to keep the number of visual tokens as small as possible while minimizing performance degradation. With just 2,000 training steps, VTR matches the performance of the full-resolution model on OSWorld, CUA-World, and video game action prediction, while using 2.5-5.8 × fewer visual tokens. These savings reduce inference cost by up to 3.3 ×

and speed up prefill by up to 2.9 ×. VTR also outperforms lowering the image res-olution and other baselines for dropping tokens, by up to 12.8 points on OSWorld. Overall, VTR enables computer-use agents to process only the visual tokens they need, allowing them to be used in long-horizon tasks and real-time domains at a fraction of the computational cost. 1

## 1 Introduction 

Computer-use agents (CUAs), which operate software by observing screenshots and issuing mouse and keyboard actions, have recently achieved superhuman performance on several long-horizon benchmarks [Xie et al., 2024, Aggarwal et al., 2026b,a]. However, their computational cost limits their use in long-horizon tasks and real-time domains such as video games [Aggarwal et al., 2026a, Abhyankar et al., 2026]. A key bottleneck is the representation of each screenshot as thousands of visual tokens, which accumulate into long contexts as agents reason over extended histories of interaction. For instance, Qwen3.5 [Qwen Team, 2026] encodes a single 1080p screenshot into about 2,000 visual tokens, so an agent that keeps its full history on a 100-step task has over 200,000 visual tokens in its context by the final step. In video games, agents observe the screen many times per second, and even at a reduced resolution of 640 × 360 , one minute of play at 30 frames per second amounts to about 400,000 visual tokens. Furthermore, in real-time environments, speed is the primary bottleneck for frontier agents [Aggarwal and Welleck, 2026]. Existing methods reduce the number of visual tokens by keeping the tokens that receive the most attention within each image [Chen et al., 2024, Yang et al., 2025], or by dropping tokens that remain

However, these hand-designed rules keep a fixed fraction of tokens or apply a fixed threshold to every input, regardless of what the agent needs for its next action. Other work learns which visual tokens to keep jointly with the model for single images in general visual question answering [Huang et al., 2025, Ye et al., 2025]. However, computer-use agents face fundamentally new challenges, such as long histories of nearly identical screenshots, and actions that depend on small regions of the screen, like a cursor or a single spreadsheet cell. We observe that most visual tokens in an agent’s history are either semantically irrelevant to its next action or temporally redundant across screenshots. For instance, the taskbar and the empty parts of a document rarely affect the agent’s next click, and consecutive game frames share most of their background. Building on this observation, we introduce Visual Token Routing (VTR), a joint training framework for learning sparse visual representations that preserve the information needed for action prediction (§2; Figure 1). In VTR, a lightweight spatio-temporal router processes each image region across the current and previous screenshots and outputs a decision to keep the visual token or not. Dropped tokens are removed from the input sequence, so the language model processes only the kept tokens, which retain their original positional encodings. We train the router jointly with the language model to satisfy two objectives: (1) keeping as few visual tokens as possible, and (2) preserving the model’s accuracy in predicting the agent’s next action. However, training the router poses two challenges. First, dropping a token is a discrete decision that provides no gradient to the router, which we address by scaling each kept token by its keep probability, as in mixture-of-experts models [Shazeer et al., 2017, Fedus et al., 2022]. Second, unlike mixture-of-experts models, where each token is processed by a fixed number of experts, the router must also decide how many tokens to keep. We therefore measure how much the screenshots help the model predict each action, using reference models trained with and without them, and adaptively weight the two objectives so that the model keeps this benefit while dropping tokens. In doing so, the router learns how many visual tokens each input needs while preserving the model’s performance, rather than relying on a fixed token budget. We use VTR to train vision-language models on computer-use trajectories and video game play, and evaluate them on OSWorld [Xie et al., 2024], CUA-World [Aggarwal et al., 2026b], and video game action prediction. With just 2,000 training steps, VTR matches the performance of the full-resolution model in all three domains, while using 2.5-5.8 × fewer visual tokens (Figure 4). These savings reduce inference cost by up to 3.3 × and speed up prefill by up to 2.9 × (Figure 5). In addition, VTR outperforms lowering the image resolution and hand-designed rules for dropping tokens, by up to 12.8 points on OSWorld. Furthermore, we find that learning visual token selection jointly with the model is crucial, improving performance by 13.2 points on OSWorld over the same router trained separately from the model. 2In summary, our contributions are three-fold. First, we introduce Visual Token Routing (VTR), a joint training framework for learning sparse visual representations, in which a lightweight spatio-temporal router decides which visual tokens enter the language model. Second, we propose a dual objective that trains the router to keep as few visual tokens as possible while preserving action pre-diction, so that the router learns how many visual tokens each input needs without a fixed token budget. Third, through extensive evaluations, we show that VTR matches full-resolution perfor-mance on OSWorld, CUA-World, and video game action prediction with 2.5-5.8 × fewer visual tokens and up to 3.3 × lower inference cost, that it outperforms other token reduction approaches, and that learning visual token selection jointly with the model is crucial. 

## 2 Visual Token Routing 

2.1 Problem Setup 

Our goal is to reduce the number of visual tokens that a computer-use agent processes at each step, without degrading the actions that it takes. Next, we describe how such an agent observes and acts, and then formalize our method, Visual Token Routing (VTR). 

Computer-use agents. A computer-use agent performs a task specified by a natural-language in-struction p over multiple steps. At each step t, it receives an observation ot, such as a screenshot of a desktop or a frame of a video game, and takes an action at, such as a mouse click or a key press. The agent chooses at based on its interaction history ht = ( p, o 1, a 1, . . . , o t−1, a t−1, o t), and we model it as a vision-language model πθ that predicts at ∼ πθ (· | ht).

Visual tokens. The vision encoder of πθ maps each observation oτ to N visual tokens 

vτ, 1, . . . , v τ,N ∈ RD , one per image region, where D is the hidden size of the language model. For instance, N = 2 ,040 for a 1080p screenshot in Qwen3.5-2B [Qwen Team, 2026]. As each observation in ht contributes N tokens, the language model processes tN visual tokens at step t.

Visual token routing. A router assigns each visual token a gate gτ,j ∈ { 0, 1}, and the language model receives the routed history ˜ht, which contains vτ,j only if gτ,j = 1 , along with all text and action tokens. Dropped tokens are removed from the input sequence, so the language model does not process them. Our goal is to minimize the fraction of kept visual tokens,

Anchors. We group observations into blocks of B consecutive observations and call the first ob-servation of each block an anchor (Figure 2). Anchors are kept in full, and the router acts only on the other observations in a block, with its history starting at the anchor. The anchor gives the model a full view of the screen to compare later observations against, and each new block refreshes this view, so regions that the router keeps dropping are never out of date for long. 

Sliding router. We also consider a sliding variant, in which only the first observation is kept in full, and the router’s history is a rolling window of the K previous observations without block boundaries. This variant avoids the cost of periodic anchors and uses the same trained router. 

2.3 Training 

Training the router requires balancing two goals: keeping as few visual tokens as possible and preserving the accuracy of action prediction (Figure 3). A natural objective is a weighted sum of the two, 

L = Ltok + λ Ldeg , (4) where Ltok is the expected fraction of kept tokens, Ldeg measures how much dropping tokens hurts action prediction, and λ is a weight. This raises two questions: how to measure Ldeg , and how to set λ. For the first question, the loss of πθ alone is not enough, since some actions are hard to predict even from the full history, and others can be predicted from the anchors alone. We therefore compare πθ against two reference models: one that sees the full history and one that sees only the anchors. For the second question, the right λ is unknown in advance, since a large λ keeps too many tokens and a small λ loses too much accuracy. Joint training. Since πθ was pre-trained on full images, we train it jointly with the router so that it learns to predict actions from the kept tokens alone. At each training step, we sample gates for each example and update πθ and the router with the cross-entropy loss of πθ given only the kept tokens. We then sample a second set of gates and update only the router with Eq. (4), keeping πθ fixed. The full and blind models are initialized from the same model as πθ and trained with the cross-entropy loss on the same examples, so that in and dn reflect differences in the input rather than in training. At inference, we use only πθ and the router, so the reference models add no cost. 

Initialization. In joint training, the router learns which tokens matter only through the loss of πθ ,which gives a weak signal when the router starts from random weights. We therefore first train the router alone to predict simple labels based on §1: a token is labeled as kept only if its region changed from the previous observation, so that it is not temporally redundant, and belongs to an object segmented by SAM [Kirillov et al., 2023], so that it is likely semantically relevant. Joint training then starts from this router and refines its decisions based on what the agent needs for its next action. Further details are in Appendix A.3.

Baselines. We compare VTR with the following ways to reduce visual tokens, all using the same model and training data: 1. Lower resolution: the dense model, which processes every visual token, with each image resized to 50%, 25%, or 12.5% of its area. 2. Pixel-diff: keeps only the regions whose pixels changed from the previous observation, following methods that drop tokens repeated across video frames [Choudhury et al., 2024, Bagrov et al., 2025] and screenshots [Abaskohi et al., 2026]. 3. H.264: keeps only the regions that the H.264 video codec [Wiegand et al., 2003] encodes as moved or changed, following methods that select visual tokens from the motion vectors and residuals of video codecs [Tang et al., 2026, Sarkar et al., 2026]. 4. We also evaluate VTR with the sliding router (§2.2), and with images resized to half or a quarter of their area.

VTR outperforms other token reduction approaches. Figure 4 also compares VTR with two other ways to reduce visual tokens: lowering the image resolution, and hand-designed rules that keep the regions that changed between observations, namely pixel-diff and H.264. At every number of tokens where both are measured, VTR achieves higher performance than the dense model at a lower resolution. For instance, on OSWorld, VTR scores 2.9 points higher than the dense model at half the image area, while using fewer tokens. Lowering the resolution removes detail from every region of the screen, including the small regions that actions depend on, like a cursor or a spreadsheet cell, whereas VTR keeps the regions it selects at full resolution. VTR also outperforms both hand-designed rules on every benchmark. On OSWorld, for instance, VTR scores 18.1, compared with 9.4 for H.264 and 5.3 for pixel-diff. Unlike these rules, which decide what to keep from the pixels alone, VTR learns what the agent needs for its next action in each domain. Moreover, VTR is complementary to lowering the resolution: combined with a quarter of the image area, it reduces visual tokens by 23 × in video games, with only a small drop in click accuracy. These results show that learning which regions to keep preserves more of what the agent needs than lowering the resolution or applying a fixed rule. 

Learning which tokens to keep jointly with the model is crucial. To isolate the effect of joint training, we compare VTR with a frozen router, which starts from the same initial router (§2.3) but keeps it fixed while training the language model. On OSWorld, VTR scores 18.1, compared with only 4.9 for the frozen router, which performs similarly to pixel-diff. This is expected, since the initial router is trained on a similar rule, keeping regions that changed and belong to an object, and training the language model alone cannot recover the regions that this router drops. In video games, VTR also achieves higher click accuracy than the frozen router, although the gap is smaller. 4.2 Analysis VTR makes inference cheaper and faster. Since VTR removes most visual tokens, each step of the agent also costs less and takes less time. Figure 5 shows the performance of each method against its inference cost and its prefill time, the time the model takes to process its input before generating an action. VTR reduces the cost by 2.4 × on OSWorld, 1.8 × on CUA-World, and 3.3 × in video games, and speeds up prefill by 2.3 ×, 2.2 ×, and 2.9 ×. These gains are smaller than the reduction in visual tokens, since VTR removes only visual tokens, while the instruction, the previous actions, and the generated action stay the same. Moreover, VTR is both cheaper and faster than the dense model at half the image area in all three domains, while achieving higher performance. These results show that the token savings of VTR translate into lower cost and faster inference, while matching full-resolution performance.

VTR adapts how many visual tokens it keeps to each domain and game. Since we never fix the number of kept tokens (§2.3), the router decides how many tokens each input needs. To see how this number varies, we group the video games by how much of the screen changes between consecutive frames, from games like Candy Crush, where little of the screen moves, to games like Counter-Strike 2, where most of it does. Figure 6 shows the percentage of vi-sual tokens each method keeps. VTR keeps 2.7% of the tokens in games with low motion, 5.9% in games with high motion, and 26.3% on desktop tasks. Interestingly, as more of a game screen changes, VTR keeps only a few more tokens, while pixel-diff and H.264 keep many more. This is likely because many regions that change, such as the background moving as the camera turns, do not affect the agent’s next ac-tion. On desktop tasks, in contrast, VTR keeps more tokens than pixel-diff, likely because the agent often needs regions that did not change, such as text it has to read. These results show that VTR decides how many visual tokens to keep based on what each input needs, rather than on how much of the screen changes. 

VTR keeps the regions the agent needs for its next action. To see which regions the router keeps, Figure 7 shows the previous observation and the regions that VTR keeps in the current one. In Dota 2, a fight takes place on an otherwise static map, and VTR keeps 23 of the 220 regions, mostly the fighting units and their health bars. In Candy Crush, the player moves a single candy, and VTR keeps only the region of that candy. In Minecraft, VTR keeps the opponent and the health 8counter that dropped from 13 to 11, and drops the field around them. Interestingly, in Gpredict, VTR keeps the region where a tooltip disappeared, so it also treats the removal of an element as information, while it drops the satellite map behind the dialog. VTR also keeps a few isolated regions in static areas, likely because each gate is sampled from its keep probability. Overall, rather than just detecting motion, the router appears to keep the changes that the model cannot infer from earlier observations, such as a lower health counter or a closed tooltip, and to drop those it can, such as the shifted background when the camera moves in GTA V (Appendix B.1). ## 5 Related Work 

Visual token reduction. Many methods reduce the visual tokens of vision-language models with-out training, by keeping the tokens that receive the most attention [Chen et al., 2024, Yang et al., 2025, Zhang et al., 2025b], merging similar tokens [Bolya et al., 2023, Shang et al., 2025], or drop-ping tokens that repeat across video frames, detected from pixels or from video codecs [Shen et al., 2025, Bagrov et al., 2025, Choudhury et al., 2024, Tang et al., 2026, Sarkar et al., 2026]. Other methods train a module that predicts which tokens to keep [Rao et al., 2021, Huang et al., 2025, Ye et al., 2025, Wang et al., 2026a]. However, all of these methods set the number of kept tokens in advance, as a fixed ratio, a fixed threshold, or a target token count. In contrast, VTR trains its router jointly with the language model and keeps as many tokens as the model needs to preserve its accuracy. 

Efficient computer-use agents. Computer-use agents take far longer than humans to complete tasks [Abhyankar et al., 2026, Aggarwal et al., 2026a], and latency limits them in real-time domains such as video games [Zhang et al., 2025a, Aggarwal and Welleck, 2026]. To reduce the cost of screenshots, agents commonly keep only the last few screenshots in context [Qin et al., 2025, Wang et al., 2025a, Anthropic, 2026], and methods designed for GUI agents skip, prune, or compress visual tokens [Lin et al., 2025, Xu et al., 2026, Huang et al., 2026, Chen et al., 2025, Wang et al., 2026b, Abaskohi et al., 2026]. However, these methods either discard older screenshots entirely, or decide what to drop with fixed rules or a selector trained separately from the model that predicts actions. In contrast, VTR learns which tokens to keep together with the model, based on what the agent needs for its next action. 

Learned routing and constrained optimization. Mixture-of-experts and Mixture-of-Depths models learn to route tokens through parts of the network [Shazeer et al., 2017, Fedus et al., 2022, Zhou et al., 2022, Raposo et al., 2024], and adaptive computation methods let the amount of com-putation vary across inputs [Graves, 2016, Wang et al., 2025b, Schuster et al., 2022]. Separately, constrained optimization adapts a Lagrange multiplier during training to meet a target, for example in VAEs, reinforcement learning, and pruning [Rezende and Viola, 2018, Tessler et al., 2019, Wang et al., 2020, Gallego-Posada et al., 2022]. However, these methods fix the amount of computation, set a target for it, or calibrate it only after training, rather than constraining the model to keep its accuracy during training. In contrast, VTR minimizes the number of kept tokens subject to the model not losing accuracy, and enforces this constraint during training by dual ascent. Appendix C provides an extended discussion of related work. 

## 6 Conclusion 

In this work, we introduced Visual Token Routing (VTR), a joint training framework that enables computer-use agents to process only the visual tokens they need. By training a lightweight spatio-temporal router together with the vision-language model to keep as few visual tokens as possible without losing accuracy, VTR addresses a key computational bottleneck of computer-use agents, which arises from representing each screenshot with thousands of visual tokens. VTR matches the performance of the full-resolution model on OSWorld, CUA-World, and video game action prediction with 2.5-5.8 × fewer visual tokens, reducing inference cost by up to 3.3 × and speeding up prefill by up to 2.9 ×, and outperforms lowering the image resolution and other baselines for dropping tokens. We further show that learning which tokens to keep jointly with the model is crucial. Our analysis also shows that the router learns on its own how many tokens to keep for each input and domain, keeping only regions that matter for the agent’s next action. By learning what 9an agent needs to see, VTR makes it possible to use computer-use agents in long-horizon tasks and real-time domains at a fraction of the computational cost.

A.1 Training Data 

The training data contains 4,265 computer-use examples from the CUA-World training split [Ag-garwal et al., 2026b] and 29,401 video game examples from the markov-ai/gaming-500-hours 

dataset, and we sample computer-use and video game examples at a ratio of 1:3. Each example con-tains up to 20 screenshots for computer use and 40 frames for video games, with older steps given as text, and we compute the cross-entropy loss on every token of the target action. 

A.2 Router Architecture 

The router’s input concatenates the visual tokens of K + 1 = 11 observations, which gives 11 ×

2,048 = 22 ,528 dimensions. The MLP has layers of size 22,528, 1,024, 256, and 1, with GELU activations and a dropout of 0.1, for a total of 23.3M parameters. Requests with a single observation are kept in full. 

A.3 Initialization 

For the initialization labels (§2.3), a region counts as changed if its mean absolute pixel change from the previous observation is at least 10 out of 255. We train on windows of 11 observations and supervise only the last one, using 47,489 computer-use windows and 29,709 video game windows. We train the router with a binary cross-entropy loss for 558 steps, with a batch size of 1,024 and AdamW with a learning rate of 1.5 × 10 −3.

## C Extended Related Work 

This appendix expands on the related work in §5. 

Visual token reduction. Vision-language models represent each image with hundreds to thou-sands of visual tokens, and a large body of work reduces this number to speed up inference. Training-free methods score tokens by attention, either inside the language model, as FastV [Chen et al., 2024] does after its second layer, or in the vision encoder, as VisionZip [Yang et al., 2025] does, while Spar-seVLM [Zhang et al., 2025b] scores visual tokens by the attention they receive from the relevant text tokens. Token merging combines similar tokens instead of dropping them, first in vision trans-formers [Bolya et al., 2023] and then in vision-language models, where LLaVA-PruMerge [Shang et al., 2025] also chooses the number of kept tokens for each image with an outlier rule on attention scores. For video, methods exploit redundancy across frames: LongVU [Shen et al., 2025] drops near-duplicate frames and reduces tokens based on their similarity across frames, EVS [Bagrov et al., 2025] removes patches that stay the same across consecutive frames while keeping the posi-tions of the remaining tokens, and run-length tokenization [Choudhury et al., 2024] replaces patches that repeat over time with a single token. Codec-based methods instead read the motion vectors and residuals that video codecs already compute: OneVision-Encoder [Tang et al., 2026] selects the patches with the strongest motion and residuals across frames, up to a fixed token budget, and trains its vision encoder on these sparse inputs, while CoPE-VideoLM [Sarkar et al., 2026] encodes only keyframes with the image encoder and represents the other frames with a few tokens built from motion vectors and residuals. Learned methods train a module that predicts which tokens to keep together with the model, starting with DynamicViT [Rao et al., 2021] for image classification and ex-tending to vision-language models with Dynamic-LLaVA [Huang et al., 2025] and ATP-LLaVA [Ye et al., 2025], while VideoLLM-MoD [Wu et al., 2024] learns which video tokens skip the compu-tation of each layer. However, in all of these methods, the number of kept tokens is set by hand: training-free methods use a fixed ratio or threshold, codec-based methods use a fixed token budget or 16 GTA V: the camera follows the motorcycle Candy Crush: the player moves one candy    

> Candy Crush: new candies fall into the board Minecraft: a fight with another player
> Dota 2: a fight on an otherwise static map Gpredict: the agent types a satellite name
> LibreCAD: the agent opens a menu PsychoPy: the agent names a new routine

Moreover, apart from the video methods, they decide for each image independently. SCORE [Wang et al., 2026a] comes closest to our work. A small MLP reads each video token together with its change since the previous frame and outputs a keep probability, and the MLP is trained with reinforcement learning on sampled keep masks. How-ever, SCORE keeps the vision encoder and the language model frozen, looks only one frame back, and keeps a fixed fraction of tokens at inference by selecting the highest-scoring ones. In contrast, the router in VTR reads each image region across several previous screenshots and is trained jointly with the language model, so the model learns to act from the kept tokens, and the number of kept tokens is not set in advance but chosen so that the model does not lose accuracy. 

Efficient computer-use agents. As computer-use agents improve on benchmarks such as OS-World [Xie et al., 2024], recent work has turned to their speed and cost. OSWorld-Human [Ab-hyankar et al., 2026] finds that agents take tens of minutes on tasks that humans complete in a few minutes, with later steps taking up to three times longer than early ones, and cua-speedrun [Aggar-wal et al., 2026a] standardizes the infrastructure for measuring the speed and cost of agents across benchmarks. In real-time domains, VideoGameBench [Zhang et al., 2025a] identifies inference la-tency as a major limitation of frontier models in video games, and in Gym-Anything-RT [Aggarwal and Welleck, 2026], the pass rate of a frontier agent rises from 9.0% to 75.0% when the environ-ment is paused while the agent decides. To limit the cost of screenshots, agents commonly keep only the last few screenshots in context and represent earlier steps as text [Qin et al., 2025, Wang et al., 2025a], and Anthropic recommends reducing the resolution of screenshots and keeping only the most recent ones [Anthropic, 2026]. Methods designed for GUI agents reduce tokens more se-lectively. ShowUI [Lin et al., 2025] groups patches of similar color into connected components and skips part of the patches in each component, GUIPruner [Xu et al., 2026] lowers the resolution of older screenshots and prunes the current one with rules that preserve its layout, GUI-KV [Huang et al., 2026] compresses the key-value cache by scoring how redundant older screenshots are given 17 the current one, and SimpAgent [Chen et al., 2025] trains the model to drop all history screenshots after a fixed layer. STP-GUI [Wang et al., 2026b] learns a token selector with reinforcement learn-ing, but keeps the model frozen and keeps a fixed fraction of tokens. However, none of these methods learns which tokens to keep together with the model that predicts actions. ReVision [Abaskohi et al., 2026] comes closest to our work. A three-layer MLP compares each patch with the same patch in the previous screenshot and drops unchanged patches, the first screenshot in the window is kept in full, and kept patches retain their original positions. However, ReVision trains its MLP on labels obtained by matching regions from a UI parser across screenshots, and only then fine-tunes the model on the filtered trajectories, so the MLP detects unchanged content rather than learning what the agent needs for its next action. In contrast, VTR starts its router from similar labels, which combine changed regions with segmented objects (§2.3), and then trains the router jointly with the model to preserve action prediction, on desktop tasks and video games. 

Learned routing and constrained optimization. Conditional computation trains a router to de-cide which parts of a network process each input. Sparsely gated mixture-of-experts models route each token to its top-scoring experts [Shazeer et al., 2017, Fedus et al., 2022], expert choice routing lets each expert pick a fixed number of tokens [Zhou et al., 2022], and Mixture-of-Depths [Raposo et al., 2024] applies the same idea across layers, sending a fixed number of tokens through each block while the rest skip it. In these models, the router’s weight scales the output, which gives the router a gradient despite the discrete choice, while other methods train discrete gates with the straight-through estimator [Bengio et al., 2013] or with continuous relaxations such as Gumbel-softmax [Jang et al., 2017, Maddison et al., 2017]. Adaptive computation methods let the amount of computation vary across inputs, by learning when to stop computing under a penalty on the amount of computation [Graves, 2016, Yin et al., 2022], or by activating a variable number of ex-perts [Wang et al., 2025b, Guo et al., 2025], where ReMoE [Wang et al., 2025b] adapts the weight of its sparsity penalty to reach a target average sparsity. Separately, constrained optimization replaces hand-tuned loss weights with Lagrange multipliers that are adapted during training to meet a target, as in constrained VAEs [Rezende and Viola, 2018], constrained reinforcement learning [Altman, 1999, Tessler et al., 2019, Stooke et al., 2020], and pruning to a target sparsity [Wang et al., 2020, Xia et al., 2022, Gallego-Posada et al., 2022]. However, methods that reduce computation fix its amount, set a target for it, or weight it with a hand-tuned penalty, so they do not ensure that the model keeps its accuracy. CALM [Schuster et al., 2022] comes closest to our work, letting each token exit the language model early and calibrating the exit thresholds after training so that, with high probability, the outputs stay close to those of the full model. In contrast, VTR minimizes the number of kept tokens subject to the model not losing accuracy, measured against reference mod-els with and without the full history, and enforces this constraint during training by dual ascent. Like mixture-of-experts models, VTR scales each kept token by its keep probability, but it removes dropped tokens from the input entirely, so they cost no computation in any layer. 18
